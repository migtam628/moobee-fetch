# MooBee Fetch v0.2.2 — egress-isolation lab

**State:** isolated opt-in **candidate**, NOT deployed or enabled on the VPS.
MooBee Stream/IPTV/StreamBoss and their Docker/network settings are out of
scope. No public torrent ports are opened and no running services are touched.

## Why

Diagnostics on the Stream VPS (2026-10-12) showed:

- Both host and Docker can send/receive ordinary UDP packets.
- Two external DHT bootstrap servers responded in both places.
- The official Ubuntu tracker returned peer information; the one peer that
  completed a BitTorrent handshake did **not** advertise BEP-10 extended
  messaging. Thus magnet `ut_metadata` could not complete through it.
- Valid `.torrent` files bypass magnet metadata retrieval, but still need
  reachable peers for content.
- MooBee Fetch v0.2.1 intentionally leaves trusted tracker profiles OFF
  until network isolation is tested.

## Added in v0.2.2

- `compose.egress.yaml`: **explicit opt-in** override affecting only the
  MooBee Fetch downloader. Base `compose.yaml` is untouched.
- `services/downloader/Dockerfile.egress`: separate image with `iptables`
  and `gosu`. The init process temporarily has root plus NET_ADMIN
  **in the downloader container network namespace**, not the host namespace.
- `egress-entrypoint.sh` installs fail-closed filter OUTPUT policy. It
  allows established RPC replies and container-local loopback/Docker DNS,
  rejects reserved/private IPv4 destinations including RFC1918, CGNAT
  100.64/10 (Tailscale), 169.254/16 cloud metadata, local Docker networks,
  special-use ranges; also rejects an explicit `FETCH_HOST_PUBLIC_IP`
  (hairpin access back to this VPS), then permits public IPv4. IPv6 OUTPUT
  policy defaults DROP. If iptables cannot load, downloader does not start.
  Only afterward runs the standard aria2 command as **uid 10001**.
- `scripts/test-egress-lab.sh`: ephemeral Docker network, synthetic local
  private HTTP service, one protected disposable downloader namespace,
  negative private-IP connection test and positive public TCP/DNS tests.
  Downloads a **synthetic local 40 KiB** file with aria2 over loopback and
  verifies its SHA-256. Cleans up test containers, network, image.
  Does not download any third-party media.

## Critical limitations

**Not a full VPN or general host firewall.** This protects outbound
connections originating in the *container network namespace* only. It does
not guarantee isolation against:
- public-IP aliases of internal hosts, DNS relays/proxies, host port
  forwarding, malicious public proxies, or all possible NAT/hairpin routes;
- traffic arising outside the downloader namespace, including the web
  container or other services;
- host administration by another Docker-capable user;
- exposure of this VPS public IP to BitTorrent peers.

The opt-in overlay grants NET_ADMIN to the downloader **startup container**.
Despite dropping to uid 10001 for the daemon, this is a security tradeoff
and needs explicit operator approval. A bridged Docker network by itself is
NOT an egress firewall. The startup script enforces no-inbound-port
publication; leave it that way.

A synthetic HTTP download only verifies basic aria2 byte transfer and file
integrity; it is **NOT** a successful BitTorrent/metadata test. A later
verified legally distributable `.torrent` download should be run with
adequate storage and bandwidth, after firewall approval. The 20 GiB parser
cap only protects uploaded metainfo, **not magnet downloads**.

## Gate A — disposable lab on the Stream VPS

Before doing anything, verify currently running services and backups. Do
not execute this lab without approval to create short-lived Docker
containers and a temporary bridge network on this VPS.

```bash
cd /opt/moobee-fetch
docker compose ps
curl -fsS http://127.0.0.1:8091/health
bash scripts/test-egress-lab.sh
```

Look for:

```text
Unprotected private control: REACHABLE
MooBee Fetch isolated IPv4 outbound policy installed; IPv6 egress blocked.
PASS: Private Docker network address blocked
DNS resolution: PASS
Public IPv4 TCP 443: REACHABLE
PASS: aria2 transferred synthetic file and SHA-256 checksum matches
=== EGRESS LAB PASS ===
```

If rootless Docker, NET_ADMIN restrictions, kernel nftables, or security
policy prevent firewall setup, lab must FAIL. This is not a reason to
weaken the rules or touch the VPS firewall blindly.

## Gate B — opt-in live downloader overlay (requires explicit approval)

Do **not** run this section yet. It changes only the MooBee Fetch
downloader and briefly pauses live transfers.

1. Back up `/opt/moobee-fetch/.env`, `compose.yaml`,
   `data/downloads/.aria2-session`, and current Git/source revision.
2. Require `FETCH_HOST_PUBLIC_IP` for the opt-in overlay. On the current
   Stream VPS, value is `209.159.148.172`; confirm it hasn't changed.
3. Confirm CI and lab pass, and review NET_ADMIN/security tradeoff.
4. Explicitly run **both Compose files** for egress deployment:

   ```bash
   cd /opt/moobee-fetch
   export FETCH_HOST_PUBLIC_IP=209.159.148.172
   docker compose -f compose.yaml -f compose.egress.yaml config --quiet
   docker compose -f compose.yaml -f compose.egress.yaml up -d --build --no-deps downloader
   docker compose -f compose.yaml -f compose.egress.yaml ps
   ```

5. Check logs (do not share .env or secrets), RPC health and connections.
   Confirm private addresses remain inaccessible from actual downloader
   namespace, and that the web container's authenticated RPC still works.
6. Only after verifying the egress policy should the operator consider
   setting `FETCH_CURATED_TRACKERS_ENABLED=1` on the **web service**
   (restart web alone). This is **not automatic**; do not enable until
   the user explicitly approves it.

Rollback downloader to original base image/namespace behavior:

```bash
cd /opt/moobee-fetch
docker compose -f compose.yaml up -d --build --no-deps downloader
```

Do not run setup.sh, delete `data/`, or use `docker compose down -v`.
Do not apply host-level iptables/nftables rules. Host and web service
settings remain unchanged. Continue with a legal official small-file
BitTorrent control after approval, verify checksum, and inspect peers
and storage growth.

## Exit conditions for v0.2.2

- The disposable lab passes on the target host (or installation is held).
- Existing MooBee Fetch stays accessible on `127.0.0.1:8091`.
- No impact on existing MooBee Stream containers/network/ports.
- Operator explicitly approves any live overlay restart and tracker opt-in.
- No broad claims of a fixed 0 B/s issue until a real authorized BitTorrent
  transfer completes with checksum.

# MooBee Fetch v0.2 — Isolated staging and rollout

**Status: not deployed.** This v0.2 follow-up is separate from MooBee Stream
(`/opt/moobee-stream`), MooBee IPTV gateway, its database, and its containers.
No new published ports, public access, tailnet access, or firewall rules.

## What's implemented

- Download diagnostics: authenticated read-only `GET /api/diagnostics` shows
  the aria2 DHT flags and configured TCP/UDP peer-listen ports, *not* peer IPs,
  trackers, RPC secrets, or URL origins. It **does not test external UDP**.
- Per-transfer peer connection and reported seeder counters; metadata-only
  transfers now say **Finding peers / fetching metadata** rather than
  **Downloading**. They show stalled after 10 minutes without activity.
  Observation is in web-process memory; restarting the web container resets it.
  The value `0 seeders reported` does **not** mean the swarm is empty.
- New bound `--dht-file-path=/downloads/.dht.dat` saves IPv4 DHT routing
  state to the existing dedicated writable downloads mount on a clean aria2
  shutdown. This helps future discovery; it **does not fix blocked UDP or
  missing seeders**.
- Restricted `.torrent` import: POST raw `application/octet-stream` to
  `/api/transfers/torrent`. It parses at most 2 MiB metainfo, validates
  torrent file paths, a total stated size of at most 20 GiB, a maximum of
  512 files, and rejects `private=1`. Only the original info dictionary
  survives: all announce, announce-list, web-seeds, tracker URLs, nodes and
  other top-level network hints are discarded. **DHT-only**, just like magnets.
  No files or tracker URLs are uploaded to a local disk from the request.
- Existing torrent session and downloaded media stay under
  `/opt/moobee-fetch/data/downloads`, NOT the MooBee Stream media directory.
- No automatic imports, file execution or extraction.

## Major known limitations

1. A stalled transfer with `0 connections` is not proof that provider UDP
   traffic is blocked. VPS-host and Docker UDP connectivity are **unverified**.
   `NO_REPLY` from public routers and DNS servers is not conclusive.
2. This v0.2 does **not** enable arbitrary trackers or tracker extraction.
   Tracker HTTP/UDP and peer IPs can touch internal destinations unless
   stronger egress policy exists. Private-tracker torrents are unsupported.
3. Magnet links can reveal their eventual size only after metadata discovery;
   **the 20 GiB check applies to uploaded `.torrent` metainfo, not magnets**.
   Enforce host filesystem quotas/retention before unattended public downloads.
4. No internet-facing dashboard, no open BitTorrent inbound host port,
   no DNS/Caddy/Tailscale or existing Compose changes. SSH tunnel only.
5. Downloaded material is untrusted. No automatic ingestion or sharing.
6. Prefer a verified legal Linux-distribution torrent to control-test DHT
   discovery; a stalled specific swarm is not enough to diagnose the network.

## Before installing on Stream VPS

- Wait for all CI checks on the PR to turn green.
- Review `git diff` of the v0.2 PR.
- Verify the VPS is healthy: `docker compose ps` from
  `/opt/moobee-fetch` and `curl -fsS http://127.0.0.1:8091/health`.
- Do not delete/download/move existing `data/`; do not run setup again
  because it must refuse an existing `.env`.
- Preserve previous v0.1 source revision and project secrets locally.
- A clean restart of the **moobee-fetch downloader** is required to activate
  the DHT file option. That interrupts only MooBee Fetch transfers.

## Explicit operator rollout after CI and approval

First, on the **Stream VPS**, back up the live config and session **BEFORE**
transferring any new code:

```bash
cd /opt/moobee-fetch
test -s .env && test -d data/downloads
install -d -m 700 /root/moobee-fetch-state-backups
backup="/root/moobee-fetch-state-backups/$(date -u +%Y%m%dT%H%M%SZ)"
mkdir -m 700 "$backup"
cp -p .env "$backup/env.backup"
cp -p compose.yaml "$backup/compose.yaml.backup"
if test -f data/downloads/.aria2-session; then
  cp -p data/downloads/.aria2-session "$backup/aria2-session.backup"
fi
echo "Backup stored in $backup (restricted to root)."
```

From your **Mac**, using the existing clone (do not copy `.env` or `data/`):

```bash
cd ~/Desktop/moobee-fetch-deploy
git fetch origin
git checkout main
git pull --ff-only origin main
rsync -av --exclude='.git/' --exclude='.env' --exclude='data/' \
  ./ root@209.159.148.172:/opt/moobee-fetch/
```

On **Stream VPS ONLY**, once the v0.2 code is merged and synced:

```bash
cd /opt/moobee-fetch
test -s .env && test -d data/downloads
docker compose config --quiet
docker compose ps
# Changes ONLY these two Compose services in MooBee Fetch project:
docker compose up -d --build --no-deps downloader web
docker compose ps
curl -fsS http://127.0.0.1:8091/health
```

Rollback: restore source from the previous Git commit on the Mac and rsync
it again (never copy `.env` or `data/`). The timestamped root-only backup
contains the former Compose file and aria2 session. Run
`docker compose up -d --build --no-deps downloader web` from
`/opt/moobee-fetch`. Do **not** restore an older `.env` unless required.
Existing downloaded files persist.

Test GUI through your existing encrypted Mac tunnel:
`ssh -N -L 127.0.0.1:8091:127.0.0.1:8091 root@209.159.148.172`.

**Never paste passwords, original magnet URLs or RPC secrets into tickets.**

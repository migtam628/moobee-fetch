# MooBee Fetch v0.2.3: media-readiness preview

**Development only. No VPS deployment or MooBee Stream changes.**

## Implemented

The authenticated Media Readiness panel lists selected, fully completed,
physically present video files from aria2 and offers a read-only Inspect
action. The API rejects files outside the downloads mount, missing or
incomplete files, symlinks, hard links, unsupported extensions, modified
files and files larger than 20 GiB. An on-demand FFprobe process validates
a pre-opened file descriptor, uses a restricted file-only protocol,
limited analysis and a ten-second timeout, and returns container,
codec, dimensions and duration. No arbitrary file paths are accepted from
the browser.

- `GET /api/media/candidates`: completed file candidates and
  `import_enabled=false`.
- `POST /api/media/inspect`: `{"gid":"16-hex","index":1}`.
  Successful result reports `validated=true`, video details and
  `import_queued=false`. Failures return HTTP 409.
- The current fetch/download/peer logic is unchanged. No upload, import
  queue, indexing or public playback is performed.

FFprobe preflight does not prove media licensing, provenance, malware
safety, or full cryptographic integrity. A completed transfer is required.

## Stage and deployment boundaries

MooBee Fetch is the media acquisition service. MooBee Stream holds the
transcoding and HLS processing stack. The MooBee website/app and IPTV
playback authorization are separate: do not expose Stream admin keys or
signed HLS paths to public clients.

The web Docker image now includes FFprobe. Validate image weight, memory
and CPU in staging before deploying. The existing hardened downloader
uses both compose.yaml and compose.egress.yaml; using only the default
Compose file for a live stack update could remove the hardened configuration.
Do not change MooBee Stream, IPTV production, host firewall, DNS, ports or
running downloads during this GitHub development milestone.

## Next milestone: import worker

A separate proposal will provide a durable, explicit user-approved job
queue and worker. It must enforce idempotency, quotas and bounded file
transfer, and use Stream's server-side authenticated multipart upload API:
`POST /api/v1/admin/videos`. Stream expects a file, title and media type,
then queues transcoding. Credentials must be private to the worker. Browser
playback remains a separate authenticated gateway task.
